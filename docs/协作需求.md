# Codex 指挥 Claude Code：已确认需求

本文件记录讨论中已确定的行为。用户已确认共同理解；步骤 0 的实测结果见[最小验证记录](./最小验证记录.md)。

## 分工与会话

- Codex 负责拆解、委派、过程调整和验收，也能随时自行改代码。
- 支持新建 Claude Code 执行会话，也支持按精确会话 ID 接入既有会话；既有会话保留原工作目录。
- 新任务使用独立 Git 工作树；Codex 验收后检查改动范围和冲突，再合并到当前分支。既有目录中双方需要改同一文件时交替修改。
- 追加指令允许排队，并区分写入、提交接收、开始处理与完成；立即中断是独立动作。回执不明时先核对记录，不自动重发。
- 接入正忙的既有会话默认等当前轮结束；只有明确要求立即接管时才中断。能原位接入时优先原位接入，否则按原会话 ID 重启续接。

## 可见窗口与控制权

- 新任务自动打开可见的原生 Claude Code 交互界面，实时显示过程。先验证由终端桥管理原生界面的路径；若不能满足双向控制，再与用户讨论其他窗口形式。
- 用户在 Claude 窗口提交提示或中断，Codex 自动暂停发指令；查看、滚动和调整窗口不触发接管。
- 用户可在 Claude 窗口交还控制权，也可在 Codex 窗口要求主动接管。Codex 默认等当前轮及已排队的人类指令全部处理完；明确要求立即接管才中断。
- 关闭可见窗口仅隐藏显示，任务继续运行；取消任务须单独操作。
- 可见窗口中的 Ctrl+D 关闭该窗口并保留后台 Claude 会话；客户端退出后终端标签页自行关闭，不停留在 PowerShell 提示符。

## 配置与用量

- Claude Code 默认沿用用户启动时的当前 CCswitch／Claude Code 配置；Codex 不自行切换供应商或修改 CCswitch 配置文件，除非用户明确要求。
- 用户可指定当前配置中的模型槽位或实际模型标识，包括非 Anthropic 名称。指定模型不在当前可用配置中时拒绝启动并列出可选项。
- 运行中任务以启动时配置为目标，新任务读取最新配置；若检测到配置变化且无法保证原配置继续有效，则暂停并通知用户。Claude Code 设置热重载与 CCswitch 本地路由切换使绝对固定不可预设，见[Claude 设置](https://code.claude.com/docs/en/settings#when-edits-take-effect)和[CCswitch 路由](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/4-proxy/4.2-routing.md)。
- 单个委派任务默认最长 90 分钟、主会话最多 120 轮，可调整；子代理轮次不计入 120 轮。
- 每个 Codex 主控任务默认最多同时运行 3 个顶层 Claude 会话，可调但不超过 10 个。达到上限的新任务进入可取消队列，有空位后自动启动。
- Claude Code 保留开启子代理的能力；子代理不占顶层会话名额。每个 Claude 会话默认最多并发 8 个子代理，可调至 20。Claude Code 原生默认上限为 20，见[子代理文档](https://code.claude.com/docs/en/sub-agents#concurrent-subagent-limit)。

## 事件、权限与交付

- 默认给 Codex 关键阶段、求助、失败和完成事件；完整日志按需查看。Codex 活跃时等待关键事件，离线期间持久保存，恢复后补读。
- Claude 默认自主执行普通本地编辑和构建。大量删除或覆盖、凭据读取或外传、远端写入、生产部署或改库、Git 推送或强制改历史，执行前由 Codex 判断；子代理继承同一门禁与宽松默认权限。
- 生产部署只有用户明确将其纳入当前任务时，Codex 才可自主批准；凭据外传不自动批准，凭据读取和远端 Git 历史改写交由用户决定。
- 门禁失联时不自动放行；用户可在 Claude 原生窗口手动处理权限，Codex 恢复后补读批准记录。若无法覆盖敏感调用，则暂停执行并通知用户；不能用可能失效后放行的普通 CLI Hook 冒充严格门禁。
- 默认使用与 `--dangerously-skip-permissions` 等效的 `bypassPermissions` 模式，同时保留 `ask: ["*"]`＋本地权限回调。普通操作由本地规则快速决定，仅敏感或不确定操作交给 Codex，避免逐条调用 Codex 模型。用户在步骤 0 中再次选择保留敏感操作门禁；无害工具的批准、拒绝、无决定和钩子异常退出已在当前 Windows／CCswitch 环境下实测，见[验证记录](./最小验证记录.md)、[权限规则](https://code.claude.com/docs/en/permissions#tool-name-wildcards)和[权限回调](https://code.claude.com/docs/en/hooks#permissionrequest-decision-control)。
- 旧插件工具接口可按实际需求调整，无需保持兼容。
- Claude 报告完成后，Codex 核对任务要求、改动范围和关键逻辑，执行相关的定向检查或构建；任务要求或确有必要时再运行全量测试。验收未通过不得合并。
- 验收问题最多退回同一 Claude 会话修复两轮；仍未通过时 Codex 接手能解决的部分，并向用户说明余项。
- 合并冲突由 Codex 解决能从任务要求判断的部分并重新验收；涉及不同业务意图的取舍交给用户决定。
- 桥接器或 Claude 异常退出时，先检查原进程是否仍运行，再按原会话 ID 自动恢复一次。状态不明或恢复失败时保留事件、暂停并通知用户。
- Claude 窗口提供专用 `/交还` 命令，并在当前环境中实测；若不可用，用户仍可在 Codex 窗口要求接管。
- 有实质代码改动的任务，默认由另一个只读 Claude Code 会话审查差异、运行定向检查并提交简短结论；纯文档或极小改动由 Codex 判断是否需要审查会话。审查会话占一个顶层并发名额。
- 审查会话不得直接改实现工作树；问题退回原执行会话，必要时由 Codex 接手。Codex 根据任务目标、改动摘要、审查结论及必要证据作最终验收，争议或高风险时再读完整代码或日志。

## 实现边界与待验证项

- 非托管且正在运行的外部 Claude 窗口无法安全地直接注入指令；目前要求原进程先退出，再按精确会话 ID 在原目录续接。托管窗口可实时交互、关闭后重开。
- 新会话、精确 ID 续接、当前 CCswitch 模型、分层回执、两条人工排队、立即接管单轮中断、子代理敏感调用、权限回调超时后的原生提示已有本机实测，详见[实现状态](./实现状态.md)。
- Windows Terminal 标签页自动关闭、人工队列同时存在时的立即中断、真实生产类操作、真实 Codex 桌面安装后的调用仍需验证。普通本地 Hook 超时或崩溃可能失去拦截能力，因此保留 `ask: ["*"]` 兜底，见[Hooks 超时规则](https://code.claude.com/docs/en/hooks#timeouts)。
