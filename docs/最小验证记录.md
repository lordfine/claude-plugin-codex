# 原生窗口最小验证记录

日期：2026-09-23。状态：步骤 0 部分通过，仍有待验证项。本轮只在系统临时目录创建验证工作区和脚本；未改动用户既有 Claude 会话或生产项目。当前验证会话按原 ID 重连；桥接进程改为独立后台启动，可见窗口已连接；故障注入、自动放行和等待 Codex 的临时标记均已移除。

## 已实测

| 能力 | 结果 | 观察依据 |
| --- | --- | --- |
| Windows 原生交互界面 | 通过 | `node-pty` 创建 ConPTY，Windows Terminal 中显示 Claude Code v2.1.259 的实时交互界面；当前模型显示为 `glm-5.3-flash[1M]` |
| Codex 运行中下达短指令 | 通过 | 桥接器写入提示后，原生窗口实时显示生成过程并回复“桥接确认” |
| 关闭并重开可见客户端 | 通过 | 客户端退出时桥接器与 Claude 会话保持运行；新客户端连回同一会话并看到已有内容 |
| 按精确会话 ID 续接 | 通过 | 停止第一代桥接进程后，以原会话 ID 重新启动，历史对话与当前模型保留，后续提示得到“续接确认” |
| 指令提交与完成回执 | 通过 | `UserPromptSubmit` 与 `Stop` 事件携带同一 `prompt_id`；终端写入与 Claude 提交、完成可区分 |
| Claude 窗口 `/交还` | 通过 | 自定义命令触发 `UserPromptExpansion`，本地钩子阻止命令进入模型并在窗口显示交还提示；该次没有新的 `UserPromptSubmit` |
| 无限模式下转人工权限提示 | 通过 | `bypassPermissions` 叠加 `ask: ["*"]` 后，无决定的 `ToolSearch` 调用停在原生权限提示；按 Esc 后调用中断，未出现正常 `Stop` 回执 |
| 本地快速批准 | 通过 | 对无害 `ToolSearch` 返回 `PermissionRequest` 的 `allow`；窗口显示由钩子批准，任务完成，没有人工批准动作 |
| Codex 侧批准与拒绝 | 通过 | 本地待决文件以唯一决策 ID 关联权限请求；分别返回 `allow`、`deny`，窗口显示对应结果，拒绝的工具未执行 |
| 子代理权限继承 | 通过（无害调用） | 一个 `Explore` 子代理读取临时工作目录；其 `Bash` 权限请求带非空 `agent_id`，经过同一 `PermissionRequest` 钩子并由本地规则放行；主会话最后回复“子代理完成” |
| 权限钩子异常退出 | 通过（无害调用） | 对一次 `ToolSearch` 权限请求让钩子以退出码 42 异常结束；原生窗口出现人工确认提示，按 Esc 取消，未放行工具；故障标记已移除 |

验证只使用简短、无文件改动的模型提示。首次用 Windows PowerShell 5 启动可见客户端时，中文脚本路径被错误解码；改用 PowerShell 7 后可见窗口正常运行。该问题应在正式 Windows 启动器中直接规避。

## 可见窗口显示问题（17:08 反馈）

用户反馈重连后的 Claude 窗口有错位、空白和疑似乱码。临时桥接代码检查发现：ConPTY 固定为 120×32，未接收真实窗口尺寸；重连时还把完整历史 VT 字节流直接写入新窗口。两处都会破坏交互界面的坐标和重绘。临时脚本已改为附着时清屏、同步窗口列数与行数、触发 Claude 重绘，并在后续窗口大小变化时调用 `node-pty.resize`；终端输入改用增量 UTF-8 解码，避免多字节字符跨网络包时损坏。随后按同一会话 ID 续接，新 Windows Terminal 标签页已连接，桥接器未向 Claude 提交新提示。输出尾部未见 Unicode 替换字符，用户确认新窗口“显示正常”。这些修正现已进入正式插件；后续实证见[实现状态](./实现状态.md)。

## 窗口退出与启动参数

最初的 Windows Terminal 启动命令把未正确引用的中文标题分拆，导致 `0x80070002`，提示把“Code 验证窗口 pwsh.exe”当成可执行文件。这是启动命令错误，不是 Claude 或 CCswitch 错误。后续已用 `wt.exe new-tab pwsh.exe -NoProfile -File <启动脚本>` 成功打开并连接；不再使用 `-NoExit`，启动脚本在客户端结束时执行 `exit`。旧的 `-NoExit` 标签页已按精确进程 ID 关闭。新标签页的进程命令行确认不含 `-NoExit`；Claude 退出时标签页是否自行关闭尚未实测。

桥接进程曾随 Codex 任务中断而退出；现在改由独立后台进程持有同一 Claude 会话，并把管道名修为含进程 ID 的唯一名称。重新打开新客户端时，前一个无 `-NoExit` 标签页自行结束，后台 Claude 仍运行。客户端还新增 Ctrl+D 仅断开显示的处理；该按键路径等待用户在可见窗口确认。

## 尚未验证

- 桥接器自动识别可见窗口中的人工提交与控制权变化；本轮是观察到人工输入后由 Codex 主动暂停。
- 忙碌中追加指令的队列次序，以及工具调用中断的精确回执。
- 子代理敏感操作是否能按主会话同样转 Codex 审批；目前只验证了无害 `Bash` 调用继承钩子。[Claude 子代理钩子](https://code.claude.com/docs/en/hooks#hook-locations)
- 本地钩子**超时**时是否仍进入人工提示；本轮已经实测“钩子无决定”和“钩子异常退出”，尚未实测超时。[官方钩子超时规则](https://code.claude.com/docs/en/hooks#timeouts)
- CCswitch 配置切换后的会话固定性、现有非后台窗口的安全接入、审查会话与工作树合并。这些属于后续验证或交付阶段。

## 当前结论

原生可见窗口与运行中双向控制在本机具备可行的最小证据；`ask: ["*"]` 与 `PermissionRequest` 在当前 Windows、CCswitch 自定义模型环境下能够形成“本地快批／Codex 决策／无决定转人工”的权限路径。上述结果来自短任务验证，尚不能等同于完整插件已具备异常恢复、成本控制和敏感操作识别能力。实现方案仍按[轻量实施方案](./实施方案.md)推进。
